# 修复：登录老是掉（账号在别处登录）

## 现象

登录进去过一会儿、或者换个浏览器／换台设备打开后台，就被弹回登录页，
提示「您的账号在别处登录，请重新登录！」。

## 原因

登录状态全部压在一个地方：

- 每次登录，Users::login() 都会把新的 skey、sid 写进 gui_users 表（只有一份）；
- 浏览器里的登录 cookie（pskey / skey / sid）跟这一份比对，对不上就判定「在别处登录」，
  并且直接把 cookie 删掉（Users::checkLogin() 里那三行 Cookie::delete）。

所以只要有第二次登录，第一个就被顶掉。会触发的情况包括：

- 手机和电脑都登着，其中一个重新登录；
- 同一台机器换了浏览器、或者清了 cookie 后又登一次；
- QQ 登录走的是同一套逻辑，也会覆盖；
- 后台的 SPA 重新登录一次，前面那次就作废。

还有一点得说明：我在排查「播放器插件下载」的时候，为了验证接口，
用 admin 账号反复登录过很多次（每次 curl 登录都会覆盖 skey/sid），
这本身就会把当时正在使用的浏览器会话顶掉 —— 这也是「还是掉登录」的直接原因之一。

## 修复

1. 新增登录会话表 gui_user_session（uid / skey / sid / ip / ua / time / expire），
   每个浏览器、每台设备各一条记录，互不影响。install.sql 已同步。

2. 登录（账号密码登录、QQ 登录）时除了照旧写 cookie，还会往会话表里记一条，
   过期时间跟后台「更多设置 → 登录保持」一致。

3. Users::checkLogin() 和 getLoginUser() 改成：

   - 先在会话表里按 skey + sid 校验，查到且没过期就是有效登录（多设备各自有效）；
   - 查不到时再用用户表里的 skey/sid 兜底（这是升级前登录的老 cookie），
     并顺手往会话表补一条记录，所以升级后不需要重新登录；
   - 两边都对不上才清 cookie，提示改成「登录状态已失效，请重新登录！」。

4. 退出登录只删当前这台设备的记录，别的设备继续用。

5. 改密码、找回密码重置密码时，才会把这个用户所有设备全部下线（这是应该的）。

6. 每次登录顺手清理过期记录，并且单个用户最多保留 20 条会话，不会越积越多。

## 验证

- 用两个、三个不同的 cookie 分别登录，全部保持在线，请求接口都是正常数据（修改前第二个一登，第一个立刻掉线）
- 其中一个退出登录后，另一个仍然可用
- 清空会话表以后，用用户表里的 skey/sid 拼的老 cookie 仍然能通过，并自动补回一条记录
- 过期记录会在下次登录时被清掉；伪造的 cookie 会被拒绝
- 后台各页面（首页 / 播放器编辑 / 主题设置 / 更多设置 / 服务器状态 / 系统）全部 HTTP 200，页面里没有登录提示
- 63 个 PHP 文件语法通过，日志没有新增报错

## 升级后要做的事

如果升级时正好被登出一次，重新登录一次就行 —— 那次的 skey/sid 已经被后面的登录覆盖了。
这之后每台设备各记一条，互相不再顶。

（会话表里已经留了 ip 和 ua 字段，以后要做「登录设备列表 / 远程下线某个设备」直接在这个表上加个页面就行。）
