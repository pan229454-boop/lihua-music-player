## 一、页面上能配什么

### 1. 邮箱设置（验证码邮件 / 找回密码）

| 字段 | 说明 | 留空时 |
|---|---|---|
| 邮箱功能 | 开启 / 关闭，关闭后不再发送任何邮件 | 默认开启 |
| SMTP 服务器 | 如 `smtp.qq.com` | 用代码里的默认值 |
| 加密方式 | SSL(465) / STARTTLS(587) / 不加密(25) | SSL |
| 端口 | 可自定义 | 按加密方式自动选 465/587/25 |
| 邮箱账号 | 登录 SMTP 的完整邮箱 | 代码里的默认值 |
| 邮箱授权码 | QQ/163 要在邮箱设置里生成的**授权码**，不是登录密码 | 代码里的默认值 |
| 发件人地址 | 收件人看到的发件邮箱 | 与邮箱账号相同 |
| 发件人名称 | 收件人看到的昵称 | 代码里的默认值 |
| 邮件里站点链接 | 邮件底部"访问我们的主页"的地址 | 当前站点地址 |

页面上还有 **发送测试邮件**：填一个收件邮箱点「发送测试」，成功/失败都会直接告诉你原因（失败会显示 SMTP 的真实报错），不用去翻日志。

### 2. 登录与验证码安全

| 字段 | 说明 | 默认 | 填 0 |
|---|---|---|---|
| 登录失败上限 | 同一「用户名+IP」累计失败多少次后锁定 | 8 次 | 不限制 |
| 锁定时长(分钟) | 锁多久 | 15 分钟 | —— |
| 验证码重发间隔 | 同一邮箱多少秒内不能重复发码 | 60 秒 | 不限制 |
| 同 IP 每小时上限 | 同一 IP 每小时最多发多少封验证码 | 10 次 | 不限制 |

**改完点「确认保存」立即生效，不需要重启服务。**

## 二、这些配置是怎么生效的

```
后台「更多设置」保存
   ↓  /AdminAjax/config（参数绑定 + 键名白名单，仅管理员）
gui_configs 表（键值对，新增键自动创建）
   ↓  Common::__construct() 每次请求把整表读进配置组 web
Config::get('web.smtp_host') 等
   ↓
extend/PHPMailer/SendEmail.php   ← 发信参数全部改为读这里
app/controller/LoginAjax.php     ← 登录限速、验证码冷却/IP 上限改为读这里
```

所有字段都做了「未设置就用原来的默认值、非法值不影响运行」的兜底，所以**不填也能照常跑**，填错最坏是发信失败（会明确提示原因）。

## 三、做这个功能时顺带查出并修掉的 4 个问题

### 1. 「提示已发送验证码，但邮箱收不到」的真正原因 ⚠️

`SendEmail::SendEmail()` 失败时返回的是**错误信息字符串**（成功才返回 `true`），而 `sendcode` 里写的是：

```php
if ($result) {  // 非空字符串也是真 → 发信失败也当成功
```

所以前台永远显示「已发送验证码到邮箱 xxx」，实际上根本没发出去。**这才是之前注册/找回密码"走不完"的直接原因**（SMTP 授权码被抹掉是根本原因）。现在改为 `if ($result === true)`，并且失败原因会写进日志（前台只给通用提示，不泄露 SMTP 细节）。

### 2. 腾讯验证码上游没有超时，可能把登录挂死 ⚠️

`verifyTencentCaptcha` 用裸 curl 且没有超时设置，而上游 urlsec 接口早已失效——每次登录都要等它。现已加 3 秒连接 / 6 秒总超时，并且**没有 ticket 时直接跳过**（上游早就不可用，跳过不影响安全性，因为原逻辑对"接口失效"本来就是放行）。

登录耗时：`约 2.5 秒 → 约 0.6 秒`

### 3. 每次登录都要查一次外部 IP 归属地接口

`get_ip_city()` 每次登录/注册都会请求 `api.cenguigui.cn`（实测约 1.4 秒）。现已加**同一 IP 24 小时缓存**，重复登录不再等这一次外部请求。

### 4. SMTP 不通时会把注册/找回页面挂住 5 分钟

PHPMailer 默认 `Timeout = 300` 秒。已设成 15 秒，SMTP 配错时最多等 15 秒就返回失败。

## 四、权限与安全验证（实测）

```
管理员  GET /admin/moreset.html     → HTTP 200，13 个字段全部正常渲染
侧边菜单                            → 网站设置 / 更多设置 / 用户列表 ...（更多设置在网站设置下面）
管理员  保存配置                    → {"code":0,"message":"保存成功"}，gui_configs 立即写入
普通用户 改配置 (/AdminAjax/config)  → {"code":-1,"msg":"没有权限"}
普通用户 发测试邮件                  → {"code":-1,"msg":"没有权限"}
普通用户 打开设置页                  → 「你没有权限进入这个页面」
未登录   改配置 / 发测试邮件 / 开页面 → 「请登录后再进行操作！」
```

**配置真的生效的验证：**

```
把「登录失败上限」设为 3、锁定设为 5 分钟后：
   第1次 → 用户名不存在
   第2次 → 用户名不存在
   第3次 → 用户名不存在
   第4次 → 登录失败次数过多，请 5 分钟后再试      ← 读的是后台配置，不是写死的 8/15

把「SMTP 服务器」指向 smtp.163.com、账号 probe@163.com 后点测试邮件：
   {"code":-1,"msg":"发送失败：The following From address failed: probe@163.com<br>SMTP server error: User has no permission"}
   ← 用的是后台配置的服务器（不是代码里写死的 smtp.qq.com），并且报错如实返回

把「邮箱功能」设为关闭后发验证码：
   前台 → {"code":-1,"msg":"发送验证码失败，请联系管理员检查邮箱配置"}
   日志 → 验证码邮件发送失败：邮箱功能未开启（请到 后台 → 更多设置 → 邮箱设置 中开启）
```

测试用的配置项已全部清理，数据库回到干净状态（管理员 power=0、pie=99999，仅有原来的 13 个配置项）。

## 五、怎么用（三步）

1. **填配置**：后台 → 更多设置 → 邮箱设置，填 SMTP 服务器、邮箱账号、**授权码**（QQ 邮箱：设置 → 账户 → 开启 SMTP 服务 → 生成授权码），加密方式 SSL、端口 465。
2. **保存**：点「确认保存」。
3. **验证**：点「发送测试」，填你的收件邮箱 → 收到邮件就说明注册/找回密码的验证码功能已经可用（提示「测试邮件已发出」）。

> 配置项以明文存在数据库的 `gui_configs` 表里，页面上也只有管理员能看/改（和原来的网站设置同一套机制）。如果你希望授权码不显示在页面上，我可以改成"留空表示不修改"的形式。
