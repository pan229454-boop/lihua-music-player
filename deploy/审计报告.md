# 梨花带雨音乐播放器 · 代码审计报告

- 对象：`/root/Documents/deepseek-harness/default-workspace/lihua-music`（zip 原样解压，2175 个文件）
- 范围：84 个自有 PHP 文件（app/ config/ route/ view/ public/ extend/，不含 vendor 与 layui/adminui 主题资源）+ 模板内 JS
- 方法：静态扫描 + 鉴权分布统计 + **在部署实例 http://127.0.0.1:8080 上做未授权实测**；另有一个独立的安全审计子代理交叉复核（其结论我已逐条抽查验证）
- 本次只做检查，**未修改任何应用代码**

---

## 摘要

整体结论：**架构属于典型的小型站点代码，功能能跑，但安全边界几乎没有**。主要问题集中在四处：

1. **登录态完全建立在客户端可伪造的数据上** → 不夸张地说，"拿到这个包的人"和"能访问站点的人"都可能是管理员；
2. **几处完全未鉴权的接口，可以删用户、改数据、被当作 SSRF/任意文件读取的跳板**；
3. **随包发行的测试数据里带着管理员真实令牌和默认弱口令**，等于把后台钥匙一起发出去；
4. **web 根目录残留了调试文件**（phpinfo、debug.log、cs.php），直接泄露主机信息与一段真实会话 Cookie。

## 一、高危

### H1. 免密登录管理员：包里自带 admin 的 QQ 令牌（**已核实**）

`install.sql` 把 admin 的 QQ 绑定字段 `token` 和 API 字段 `token2` 原样打包，**实测实时库里这两个值一字未改**：

```bash
mariadb -e "SELECT uid,username,token,token2 FROM gui_users WHERE uid=1;"
# 1  admin  F313B6DE224765BCB32F381A907CA690  543CE64052142EEBA1E6CDA4794200FC
# install.sql 中也含同一串 F313B6DE...   → 发布物里的凭据就是当前生效的凭据
```

而 `app/controller/Admin.php:109 login_callback()` **没有 checkLogin**：

```php
$data = input();
if(!$data['openid'] || !$data['callback']){ ... }
elseif(!Users::checkQqToken($data['openid'])){ ... }
elseif(Users::qqlogin($data)){ ... 'QQ登录成功' ... }   // 仅凭 token 查用户 → 直接下发登录 Cookie
```

**利用**：`GET /Admin/login_callback?openid=F313B6DE224765BCB32F381A907CA690&callback=1` → 直接获得 uid=1（power=0）管理员会话，无需密码。

**修复**：① 立即重置 admin 的 token/token2/skey/sid；② 不要用带真实数据的 install.sql 建库；③ 回调必须带一次性 state/签名与时间戳。

### H2. 可把任意 QQ 绑定到任意账号（**已核实代码**）

`app/controller/Admin.php:83 set_callback($uid)` 完全没有鉴权，`$uid` 直接来自 URL：

```php
$update['token'] = $data['openid'];
... Users::updateByUid($uid, $update)   // uid 由 URL 决定
```

**利用**：`GET /Admin/set_callback/uid/1?openid=<自己的openid>&callback=x` 把自己的 QQ 绑到管理员 → 再走 `login_callback` 接管。不需要知道任何凭据。

### H3. 会话 Cookie 可离线伪造（**已实测越权成功**）

`app/model/Users.php:272 getLoginUser()` 只有一层校验，且**用客户端传来的 `skey` 当解密密钥**：

```php
$skey  = Cookie::get('skey');
$pskey = authcode(Cookie::get('pskey'), 'DECODE', $skey);   // ← 攻击者自己选密钥
$uid   = $pskey;
return $self->where('uid', $uid)->find() ?: false;
```

`authcode()`（`app/common.php:220`）是公开的 Discuz 算法。**实测**（攻击者自选 skey，伪造 uid=1）：

```bash
P=$(php -r 'require "app/common.php"; echo urlencode(authcode("1","ENCODE","attackerkey123"));')
curl -b "skey=attackerkey123; pskey=$P" http://127.0.0.1:8080/Admin/QqLoginSet -D- -o /dev/null
# → Location: .../Admin/set_callback/uid/1     ← 服务端认定我是管理员
```

**只调 `getLoginUser()` 没有 `checkLogin()` 的方法**（4 个）：

| 位置 | 危害 |
|---|---|
| `AdminAjax::password` (app/controller/AdminAjax.php:1157) | 改密码（还需原密码，但与 H1/H2 组合即成接管） |
| `AdminAjax::changeQQ` (:1165) | 改任意 uid 的绑定 QQ |
| `AdminAjax::editPlayerSongSheet` (:375) | 改任意播放器歌单 |
| `Admin::QqLoginSet` (app/controller/Admin.php:76) | 触发绑定流程 |

**修复**：pskey 必须用服务端私有密钥（env）加解密；鉴权统一走中间件；`Users::qqlogin()` 里的硬编码盐 `md5('11144452888')` 必须移出代码。

### H4. SQL 注入：`AdminAjax::config()`（**已核实代码**）

`app/controller/AdminAjax.php:1124`

```php
foreach (input('post.') as $k => $value) {
    Db::execute("INSERT INTO gui_configs SET k='" . $k . "',v='" . $value . "' ON DUPLICATE KEY UPDATE v='" . $value . "'");
}
```

键和值都未转义、未参数化（`$k` 还在列名位置）。需要登录，但 H1/H2/H3 已经给出免密进后台的路径，所以实际等于未授权可注入。
**修复**：改用 `Db::name('configs')->where('k',$k)->update()` 参数绑定 + 键名白名单。

### H5. 未鉴权的破坏性接口 + 内部方法被当接口暴露（**已实测**）

```php
// app/controller/AdminAjax.php:22  —— 没有任何 checkLogin()
public function cleanupUsers(){ $deletedUsers = Users::cleanupInactiveUsers(); ... }
```

匿名 `GET /AdminAjax/cleanupUsers` 即批量物理删除 90 天未登录的 power=2 用户并回显名单。
同类未鉴权 public 方法还有 `getCpuUsage` / `getMemoryUsage` / `getLinuxCount` / `encode_netease_data`（实测未登录可达，直接抛异常），说明 **ThinkPHP 自动路由把每个 public 方法都变成了 URL**。
另有 `Api::clearCache` 未鉴权，实测 `GET /Api/clearCache` → `{"code":0,"msg":"成功清除所有缓存"}`。

### H6. 任意账号密码重置（**已核实代码**）

`app/controller/LoginAjax.php`

```php
// sendcode(): 验证码只存 Cookie，发到攻击者自填的邮箱
$email = input('get.email'); ... Cookie::set('regcode', md5($code), 600);
// find(): 只校验验证码，不校验"这个码是发给哪个邮箱的"
// checkcode(): md5($code) == Cookie::get('regcode')   ← 松散比较
Cookie::set('regcode', 攻击者可控)
```

`app/model/Users.php:186 findpassword()` 直接 `where('mail',$mail)->update(['password'=>...])`，无原密码/归属校验。

**两条利用路径**：① 用自己的邮箱收码，再以受害者邮箱提交重置；② `Cookie: regcode=0e111111111111111111111111111111` + `code=240610708`（md5 为 `0e4620...`，PHP 松散比较 `0e` 相等）。
**修复**：验证码存服务端（session/redis）并与邮箱、用途、一次性绑定；`hash_equals` 严格比较；加频率限制。

### H7. 未授权 SSRF / 任意文件读取（**已核实代码**）

```php
// app/controller/Api.php:136  musicLyric 的默认分支
$ksc = isset($data['ksc']) ? $data['ksc'] : null;
$res = @file_get_contents($ksc, null, null, 0, 10);
if ($res) { $ksctext = send_get($ksc); $result = ['file'=>$ksc, 'txt'=>$ksctext]; }   // 内容随响应回显
```

`$ksc` 全来自 GET，`file://` / `php://` / `http://` 都支持：`/Api/musicLyric?...&ksc=file:///etc/passwd`。
同类：`Api.php:112`（type=local 的 `send_get($url)`）、`Webapi::getFavicon`（`Request::param('url')` 直接进 curl，且 `CURLOPT_FOLLOWLOCATION=true`、关闭 SSL 校验、结果原样回显，路由公开）。
**修复**：协议 + 域名白名单，禁 `file://`/`php://` 与内网段，设 `CURLOPT_PROTOCOLS`，不回显远端原文。

### H8. web 根目录的调试文件（**已实测可公网访问**）

| 文件 | 实测 | 内容 |
|---|---|---|
| `public/phpinfo.php` | 200 / 93 KB | `phpinfo()`：PHP 配置、扩展、环境变量、绝对路径 |
| `public/debug.log` | 200 / 117 KB | **作者服务器**的 `top` 全量进程表（php-fpm/mysqld 的 PID、内存） |
| `public/cs.php` | 200 | 每次请求执行 `@exec('ifconfig -a')`；**文件内明文硬编码了一组真实会话 Cookie**（`PHPSESSID/pskey/skey/sid`），并把加密结果 echo 出来；全项目无人 include（死代码） |

**修复**：三个文件直接删除；`cs.php` 里那组 Cookie 对应的会话要作废；`AdminAjax` 里写 `debug.log` 的代码一并去掉。

### H9. 随包发行的默认弱口令

`说明.md:36` 写着 `admin / 123456`；实测 `password_verify("123456", admin的bcrypt) === true`。配合 H3 的"登录无失败限制"，在线爆破门槛极低。

## 四、确认没有问题的部分（交叉复核结论）

- **密码存储正确**：主流程使用 `password_hash(PASSWORD_BCRYPT)` + `password_verify`，未回退 md5（只有 .bak 备份文件保留了旧写法）；
- **84 个自有 PHP 文件语法全部正确**（`php -l` 全通过）；
- **后台主要读取接口有鉴权**：`AdminAjax::load`、`AdminAjax::clearCache` 等未登录会被拦到"请登录后再进行操作！"；
- **无文件上传功能**（无 `move_uploaded_file`/`$_FILES`/`->file()`），故不存在上传绕过；
- **无命令/代码执行后门**：无 eval/assert/system/unserialize 携带外部输入；`shell_exec('nproc')`、`shell_exec('top -b -n 1')`、`exec('cscript ...')` 参数均为硬编码；
- **反序列化**：`config/cache.php` 的序列化开关被注释关闭，无 unserialize 调用点；
- **SQL 注入仅 1 处**（H4）：其余 `where/order/field` 全部走 ORM 参数绑定；
- **未发现第二组后门账号或万能密码分支**；未发现向固定域名隐蔽外发用户数据（外联仅限第三方音乐/授权/邮件/支付接口）。
