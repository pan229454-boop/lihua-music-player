## 一、致命：支付链路（3 项，全在收款路径上）

### F1.【已核实】支付异步通知被登录校验拦住 → 付款成功但永不发货
`app/controller/Epay.php:100/179/260` 三个 Notify 方法开头都调用了 `$this->checkLogin()`：

```php
// Epay.php:103
public function vip_Notify() {
    $data = input('get.');
    $this->checkLogin();          // ← 支付网关回调不会带用户 Cookie
// Epay.php:304
function checkLogin() {
    $check_Login = Users::checkLogin();
    if ($check_Login != null) { ... exit(View::fetch('common/error_no_console')); }  // 直接输出错误页并终止
```

**后果**：会员、播放器额度、接口额度的异步通知全部被 `exit` 拦掉，网关收不到 "success"，**用户付了钱但权益永远不到账**，且网关会不断重试。
**修复**：三个 Notify 方法删掉 `checkLogin()`（异步回调本就不该要求登录），改用订单里的 `uid` 定位用户。

### F2.【已核实】重复回调 → 主键冲突未捕获 → 500
`app/controller/Epay.php:118/197/278` 无条件执行 `Order::add($order)`，而 `gui_order` 主键是 `trade_no`。同一笔交易第二次回调 → 重复主键 PDOException → 500 → 网关继续重试。
**修复**：入库前按 trade_no 查重（或 INSERT IGNORE）+ 幂等判断放到入库之前。

### F3.【已核实】下单后取"最近一单"生成支付链接，可能指向别人/别的订单
`app/model/Pays.php:38-43`：

```php
if ($self->insert($insert)) {
    $row = $self->where('uid','=',$userInfo['uid'])->order('addtime desc')->find();  // ← 不是刚插入的那单
    $pay_url = '/Epay/submit?orderid=' . $row['orderid'] . ...;
```

`addtime` 只精确到秒、`orderid` 只加 3 位随机后缀，同一用户连点两次就可能拿到**另一单**的支付链接。
**修复**：直接用刚生成的 `$insert['orderid']`。

**附带（同一处）**：`Pays::Submit_Pay()` 的 `switch ($data['shop'])` 没有 default 分支 → shop 非法时 `$name/$money` 未定义，会建出 0 元订单。

## 二、功能不可用（已核实）

### F4. 注册 / 找回密码在非 JSON 请求下直接 500
`app/controller/LoginAjax.php:180/221` 是 `return $result;`（返回**数组**而不是 `json()`）。ThinkPHP 只在 `Accept` 含 JSON 时才自动转 JSON，否则抛 `variable type error： array`。
**实测**：
```
curl -X POST -d '...' /LoginAjax/reg        → HTTP 500（HTML 错误页）
curl -H 'Accept: application/json...' ...   → 返回 JSON
```
另外校验链走完没有兜底时 `$result` 未定义，注册失败会静默返回空。
**修复**：统一 `return json($result);` + 补 else 兜底。

### F5. `SongController` 整个类不可用
`use appmodelSongModel;`（类不存在）+ 未 use `appmodelSong` → 解析成 `app\controller\Song` → Fatal；`order('sort_order')` 这一列在 `gui_song` 里不存在（实际是 `taxis`）。**建议直接删掉该文件**。

### F6.【已实测】播放器皮肤 2/3 的 JS 取不到 → 播放器空白
`app/controller/Api.php:180` 硬编码目录：
```php
$filePath = getcwd() . '/static/guiloveyou/' . $theme . '/player/js12355555555/player.js';
```
实测目录结构：`theme=1/4..8` 是 `player/js12355555555/`，而 **`theme=2/3` 是 `player/js/`** → 取不到文件 → `json_encode(false)` → 前端 `playerScript.textContent = false`。
**修复**：按目录探测，或统一目录名（顺便把 `getcwd()` 换成 `__DIR__` 一类的绝对定位）。

### F7. 歌词接口依赖从未定义的配置
`app/controller/Api.php:128/134` 用 `Config::get('api.getksc')`，但 `Common.php:23-29` 只 set 了 `music/qq/skey` → 拼出的是 `?s=123` 这种没有主机名的 URL，curl 必然失败 → 该分支歌词永远为空。

### F8. 路由引用了不存在的控制器
`route/app.php:9`：`Route::get('ip', 'IpLocation/findLocation')`，而 `app/controller/IpLocation.php` 不存在。
**实测**：`GET /ip` → HTTP 404，页面写 `控制器不存在:app\controller\IpLocation`。
（`view/admin/serverstate.html` 请求的 `/serverStatus/*` 同样没有对应控制器，该菜单已被注释。）

### F9. 额度扣减的异常永远捕获不到
`app/controller/Webapi.php:366` `catch (DbException $e)`，但文件顶部**没有 `use think\exception\DbException;`** → 该 catch 永不命中，DB 异常直接 500。
另外此处是"先扣额度再调上游"，上游失败额度照样扣掉。

## 三、有数据丢失风险

### F10.【已核实】保存歌单是"先删后插且无事务"
`app/controller/AdminAjax.php:730-761`：
```php
$jsonData = $_POST['jsonData'];                       // 未 isset
Song::where('song_sheet_id',$songSheetId)->delete();  // 先删光
$array = json_decode($jsonData, true);                // 解析失败 = null
foreach ($array as $key => $value) { ... }            // foreach(null) → 警告
Db::name('song')->replace()->insertAll($array);       // 插入失败 → 新数据没了，旧数据也删了
```
**后果**：前端传了非法 jsonData，整张歌单的歌曲永久丢失。
**修复**：先 `json_decode` 校验是数组，再放进 `Db::transaction()` 里删+插。

### F11. `Song search` / `Song save` 的未定义变量与未判空
`AdminAjax.php:763-867` 的 `switch($data['type'])` 没有 default → 无匹配分支时 `$songs` 未定义；三处 `json_decode` 后直接取 `$arr['result']['songs']` / `$arr['data']['info']`，上游改版即 `foreach(null)` 静默返回空列表。

## 六、前后端接口不一致

1. **`msg` 与 `message` 混用**：前端框架只认 `msg`（`public/res/config.js` 的 `response.msgName='msg'`）。用 `message` 的接口，错误信息在界面上根本不显示，只弹"返回状态码异常"：
   `Users.php:143/146/175/177/180`、`UserAjax.php:61/66`、`LinkAjax.php:48/52/69/72`、`AdminAjax.php:1132/29-36`。
2. `view/user/reg.html:117`、`view/user/find.html:79` 用的是**相对地址** `LoginAjax/reg`、`LoginAjax/find`（同文件其它请求是 `/LoginAjax/sendcode` 这样带斜杠的绝对路径）→ 取决于页面所在 URL，可能 404。
3. 这两处的 `done` 回调**不看 `code` 就提示"注册成功/重置成功"** → 失败也报成功。
4. `Webapi::playlist` 用 `Request::post()` 校验却用 `Request::param()` 取值 → GET/POST 两种传参行为不一致。
5. 歌单导入的 type 取值疑似两套（`wy|kg|qq` vs `netease|kugou|qq`），**未最终确认**，需要跑一次前端才能定论。
