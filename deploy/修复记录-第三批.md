## 一、越权访问（IDOR）：8 处

原来的问题是：**只要登录了，任何用户都能操作别人的播放器和歌单**（后台接口只校验"是否登录"，不校验"是不是你的东西"）。

| 接口 | 原来能干什么 | 现在 |
|---|---|---|
| `Player/act/edit` | 改任意人的播放器（名称/主题/开关） | 校验归属 |
| `Player/act/del` | 删任意人的播放器（还给自己加 pie 余额） | 校验归属 |
| `Player/act/auth` | 给任意播放器加授权域名 | 校验归属 |
| `Player/act/delauth` | 删任意播放器的授权 | 校验归属 |
| `songSheet/act/del` | 删任意人的歌单（连同歌单内歌曲） | 校验归属 |
| `Song/act/save` | 清空/覆盖任意歌单的歌曲 | 校验歌单归属 |
| `Song/act/getPageSongs` | 读任意歌单的歌曲 | 校验歌单归属 |
| `editPlayerSongSheet` | 把**别人的歌单**挂到自己播放器上（白拿歌曲） | 过滤掉非本人歌单 |

实现方式：统一用项目已有的 `Player::checkPlayerUid()` / `SongSheet::checkSheetUid()`（注意这两个方法语义是"返回 true 表示**不是**你的"），并保留 `power=0`（超级管理员）不受限制。

**实测（服务端建了一个普通用户 + 管理员名下的播放器/歌单，用普通用户身份发起攻击）：**

```
Player/act/edit     → {"code":-1,"msg":"没有权限"}
Player/act/del      → {"code":-1,"msg":"没有权限"}
Player/act/auth     → {"code":-1,"msg":"没有权限"}
Player/act/delauth  → {"code":-1,"msg":"没有权限"}
songSheet/act/del   → {"code":-1,"msg":"没有权限"}
Song/act/save       → {"code":-1,"msg":"没有权限"}
Song/act/getPageSongs → {"code":-1,"msg":"没有权限"}
editPlayerSongSheet → 返回成功，但实际挂上的歌单数 = 0（已被过滤）

数据核查：播放器名仍为「测试播放器」、歌单仍在、授权记录 0 条 —— 攻击未造成任何改动
管理员本人操作：edit → 保存成功；del → 删除成功；getPageSongs → 获取成功（正常流程未被误伤）
```

## 二、登录失败限速（防撞库）

`LoginAjax::login` 原来可以无限次尝试密码。现在按 **用户名 + IP** 计数：15 分钟内失败 8 次即暂时锁定，登录成功自动清零。

实测：连续 10 次用不存在的账号登录 →

```
第 1–8 次 → {"code":-1,"msg":"用户名不存在"}
第 9 次  → {"code":-1,"msg":"登录失败次数过多，请 15 分钟后再试"}
第 10 次 → {"code":-1,"msg":"登录失败次数过多，请 15 分钟后再试"}
```

锁定是按"用户名+IP"的，所以不会因为别人爆破而把你的账号锁住；自己输错 8 次需要等 15 分钟。

## 三、对外请求超时（防止整站被拖死）

- `common.php` 的 `curl()`：原来只在调用方显式传 `rtime` 时才设总超时，**默认没有超时**；现补默认 30 秒。
- `common.php` 的 `send_get()`：**完全没有超时设置**（歌词、音乐 API、QQ 互联全走它）；现补连接 10 秒 / 总 30 秒。

上游接口卡住时，PHP 进程不再被无限占用。

## 四、播放器皮肤 2 和 3 空白（功能 bug）

`Api::PlayerJs` 里写死了脚本目录 `js12355555555`，但皮肤 2、3 的目录实际叫 `js`：

```
guiloveyou/1/player/js12355555555/player.js   ← 有
guiloveyou/2/player/js/player.js              ← 皮肤 2 用的是 js
guiloveyou/3/player/js/player.js              ← 皮肤 3 用的是 js
```

所以用皮肤 2/3 的播放器取不到脚本 → 页面空白。现在加了目录回退，并给 `PlayerJs`/`PlayerCss` 补了空值保护（播放器 id 不存在时返回友好结果而不是 500）。

实测（临时建了一个主题=2 的播放器）：

```
GET /Api/PlayerJs/id/主题2播放器   → HTTP 200，105811 字节真实播放器脚本
GET /Api/PlayerCss/id/主题2播放器  → HTTP 302 → /static/guiloveyou/2/player/css/player.css
GET /Api/PlayerJs/id/不存在的id    → HTTP 200（安全占位脚本，不再 500）
GET /Api/PlayerCss/id/不存在的id   → HTTP 404
```

## 五、接口提示字段统一（msg / message）

项目里错误提示有的返回 `msg`、有的返回 `message`，而前端统一读 `msg` → 用 `message` 的接口出错时用户看不到原因。已给 **17 处** `'message' => ...` 同时补上同内容的 `'msg'`（保留原字段，兼容两边），涉及 AdminAjax、LinkAjax、UserAjax、Users 模型。

## 八、仍然遗留

- **CSRF**：全站无 Token。浏览器默认 `SameSite=Lax` 能挡住跨站表单提交，但不应依赖默认值；改造成本中等（前端所有请求都要带 Token），要做请说一声。
- **Epay 的 `*_Return` 路径**：仍按"当前登录用户"发权益（权威的 Notify 路径已改为按订单归属，且 `status=2` 会互相幂等拦截，实际影响很小）。
- **`api.getksc` 配置缺失**：酷狗歌词分支取不到上游地址，永远走空歌词兜底（不报错，只是没歌词）。
- **部分 switch 缺 default**（如 `Song/act/search` 传未知 type、`songSheet` 传未知 act）。
- **默认口令 `admin/123456`** 我没动 —— 要改的话一条命令的事，说一声。
- 后台登录/注册页仍会加载已失效的腾讯验证码脚本（不影响使用，只是多余请求）。
