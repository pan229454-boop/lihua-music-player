# 新增：音乐授权（授权QQ / skey）搬到后台 + 跳过验证开关

## 需求

把原来写在代码里的「授权QQ + skey」搬到「更多设置」里，并加一个开关：

- 开关开启：显示这两个输入框，取歌时按填写的授权QQ + skey 去上游校验；
- 开关关闭：跳过授权验证，取歌直接走音乐接口，音乐正常使用。

## 改动

1. 新增配置项（gui_configs 表，install.sql 同步）：
   - auth_qq_enable：1 开启授权验证 / 0 关闭（跳过验证），默认 0
   - auth_qq：授权QQ，默认沿用原来代码里的 2963246343
   - auth_skey：skey（授权码），默认还是模板里的占位符 music-*******

2. app/common.php 新增三个判断函数：
   - auth_qq_enabled()：开关是否打开
   - auth_qq_values()：读出授权QQ / skey
   - auth_qq_ready()：开关打开、两个值都填了、且 skey 不是占位符时才去校验

3. app/controller/Common.php：授权QQ/skey 改成读后台配置，配置为空时回退到原来的默认值，
   老站点升级后行为不变。代码里原来那两行注释（"以下两个参数是你需要改的"）也跟着更新了。

4. app/controller/Api.php 的 musicUrl()：
   - 原来是无条件先去 auth.cenguigui.cn 校验，只有校验通过才去音乐接口取真实地址；
   - 现在改成：只有 auth_qq_ready() 为真才走校验，否则直接跳到「去音乐接口取地址」这一步。
   - 校验不通过时（域名未授权 / skey有误）仍然播放原来的提示音，保持上游设计的行为。

5. view/admin/moreset.html 新增「音乐授权（授权QQ / skey）」卡片：
   开关 + 两个输入框（关闭时输入框隐藏）+ 单独的保存按钮；说明里写清了两种状态的行为，
   以及「两个值没填全会自动跳过验证，不会卡住播放」。

## 验证

更多设置页：

- 默认（关闭）：开关未勾选，两个输入框容器 style="display:none"，里面显示着当前值
- 打开开关后刷新：开关勾选，输入框容器不再 display:none
- 开关联动脚本和保存按钮都在

musicUrl 行为对比（用 /api/musicUrl?sign=x&songId=1&type=qq&id=播放器ID 测）：

| 状态 | 结果 | 说明 |
|---|---|---|
| 关闭 | 音乐地址不可用，请稍后再试。 | 跳过了授权服务器，直接去音乐接口取地址 |
| 开启 + 假 skey | 请求失败，请稍后再试。 | 确实去问了授权服务器（这台机器连不上它） |
| 开启 + 占位符 skey | 音乐地址不可用，请稍后再试。 | 自动跳过验证，不卡播放 |
| 恢复关闭 + 原值 | 音乐地址不可用，请稍后再试。 | 与默认状态一致 |

测试后配置已恢复为：auth_qq_enable=0、auth_qq=2963246343、auth_skey=music-*******。

## 需要知道的两点

1. 这台机器访问上游音乐接口 musicapi.cenguigui.cn 返回 HTTP 521（Cloudflare 源站不可用），
   所以这里没法真的取到一首歌的播放地址来端到端验证「音乐能放出来」；
   代码路径是通的（跳过了授权服务器，走到了取地址这一步），实际能不能出声取决于那个接口在你那边是否可用。

2. 现在这两套皮肤（后台里那两个播放器用的是皮肤 6 和皮肤 1）的播放器脚本本身不调用服务端的
   /api/musicUrl，只有皮肤 2、3 会走这道校验。也就是说：关掉开关后，
   服务端这道授权校验对所有皮肤都不再拦人，但皮肤 6/1 的取歌方式是脚本自己决定的，
   如果它们仍然放不出声，问题在它们请求的上游接口，不在授权开关。

## 后续修正（开关不显示的 bug）

反馈：更多设置里只看到「保存」按钮，没有开关。

原因有两条：

1. 原来的开关用的是 layui 的 lay-skin="switch"。这种开关要靠页面脚本里的 form.render() 把原生 input 替换成开关样式，
   而 layui 的样式表里有一条 .layui-form input[type=checkbox]{display:none}，会把没被渲染的原生复选框藏起来。
   只要页面脚本没跑到（或者浏览器拿到的是缓存里的旧页面），结果就是：按钮在、开关不见了。
2. 后台页面之前没有禁用浏览器缓存，SPA 里翻到过的页面可能被浏览器缓存，模板改了也看不到新的。

处理：

1. 两个卡片（域名授权、音乐授权）的开关改成不依赖 layui 渲染的写法：
   原生 input + label + 自己的 css，开关样子自己画；开关与输入框、状态文字的显隐用 css 的 :checked ~ 选择器联动，
   完全不依赖页面脚本。脚本没跑、layui 没渲染，开关照样显示、照样能点。
2. 后台页面统一加上 no-store 响应头（前台页面不受影响），以后改模板刷新就能看到。
3. 保存逻辑不变，还是走 /AdminAjax/config。

验证：

- 开关关闭：input 上没有 checked，musicUrl 跳过授权验证（直接去音乐接口取地址）
- 开关开启：checked 出现、状态文字变成「已开启」，musicUrl 去问授权服务器
- 63 个 PHP 文件语法通过；后台各页 200 且都带 no-store；前台 / 与 /console 不带
