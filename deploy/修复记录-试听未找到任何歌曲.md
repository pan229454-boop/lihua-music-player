# 修复记录：试听提示「未找到任何歌曲」

现象：后台搜索歌曲能正常搜出结果，但点「试听」弹窗提示「未找到任何歌曲」。

## 原因：不是歌曲的问题，是上游音乐接口挂了

「试听」和「播放取歌」都要向音乐解析接口要一个可播放的地址，这个接口是上游官方的：

- 试听：app/model/Song.php 的 findMusicInfo() 请求 Config('api.music')，默认 https://musicapi.cenguigui.cn
- 播放：app/controller/Api.php、Webapi.php 里的取歌也走同一个地址

实测这个接口现在是宕机状态：

| 地址 | 结果 |
| --- | --- |
| https://musicapi.cenguigui.cn/ | Cloudflare HTTP 521（回源失败，源站不可达），响应 0 字节 |
| https://musicapi.cenguigui.cn/?input=0027oMO61wWi55&filter=id&type=qq&page=1&url=… | 同样 521，0 字节 |
| https://auth.cenguigui.cn/MusicApi.php | HTTP 000（完全无响应） |

接口返回空，老代码把「空」一律翻译成「未找到任何歌曲」，所以看起来像歌曲有问题，其实是接口故障。

## 为什么搜索不受影响

搜索走的是各平台官方接口（QQ 的 u.y.qq.com、酷狗的 mobilecdn、网易的 music.163.com），这些是正常的（实测 QQ 搜索一次返回 50 首），所以能搜到歌；而「取歌 / 试听」需要播放地址，只有上游那个接口提供，它挂了就取不到。

顺带说明：授权开关（跳过授权验证）也救不了这种情况，因为无论开不开，播放地址最终都要问这个接口。

## 改了什么

1. app/model/Song.php findMusicInfo()：把「接口故障」和「真的没有这首」分开报，并把接口域名带出来。
   现在试听失败会说：音乐接口暂时不可用：musicapi.cenguigui.cn 没有响应（上游服务器可能宕机了），稍后再试
2. app/common.php 新增 music_api_url() / music_api_host()：音乐接口地址可以在后台改，留空用代码里的默认值。
3. app/controller/Api.php、Webapi.php：所有取歌处（11 处）从 Config('api.music') 改成 music_api_url()，后台改地址立即全局生效。
4. view/admin/moreset.html「音乐授权」卡片：新增「音乐接口地址」输入框，保存按钮会一起提交（配置键 music_api）。

## 怎么恢复试听 / 播放

- 首选：等上游把接口修好（musicapi.cenguigui.cn 恢复），这期间它挂了全网都取不到歌。
- 或者在「更多设置 → 音乐授权 → 音乐接口地址」里填入一个可用的解析接口地址，立即切换；留空恢复默认。

## 验证

- 试听 QQ 歌曲：返回 code -2 + 「音乐接口暂时不可用：musicapi.cenguigui.cn 没有响应…」
- 试听网易歌曲：同上
- 把 music_api 改成 https://demo.example.com/music 后，报错里的域名跟着变成 demo.example.com（说明切换生效），测完已删除该测试配置项
- 63 个 PHP 文件语法通过；/ 、/console、/admin/moreset.html 均 200；页面里能看到新的 music_api 输入框


## 可用接口调研 + 内置免费兜底（续）

上游 cenguigui 整套服务都挂了（不只音乐接口）：

| 地址 | 结果 |
| --- | --- |
| musicapi.cenguigui.cn | HTTP 521（源站不可达），0 字节 |
| api.cenguigui.cn | HTTP 521 |
| auth.cenguigui.cn | HTTP 000（完全无响应） |
| www.cenguigui.cn / cenguigui.cn | HTTP 000 |

所以靠换他们家的域名是救不回来的，我把能找到的同类接口都实测了一遍：

| 接口 | 格式 | 实测 |
| --- | --- | --- |
| api.lihua.pw / music.lihua.pw / mapi.lihua.pw | 梨花带雨 | 空 |
| music-api2.qsdurl.cn / music.cxy0.cn | 梨花带雨 | 空 / 不是接口（普通网站） |
| api.5se.net、api.kxzjoker.cn、api.oioweb.cn、api.pearktrue.cn、api.lolimi.cn | 梨花带雨（试） | 空 |
| api.injahow.cn/meting、api.qijieya.cn/meting、api.i-meto.com/meting、music-api.gdstudio.xyz | Meting | 返回 HTML / 401，取不到地址 |
| 网易官方直链 music.163.com/song/media/outer/url | - | 时好时坏（302 → 404） |
| **api.vkeys.cn** | vkeys 自己的格式 | **可用**：QQ 音乐按 mid 精确返回播放地址 |

api.vkeys.cn 实测细节：

- 请求：https://api.vkeys.cn/v2/music/tencent?mid=0027oMO61wWi55
- 返回：code 200，data.url = http://ws.stream.qqmusic.qq.com/RS02…mp3?vkey=…
- 这个地址真的能播：带 Range 请求返回 HTTP 206、audio/mpeg
- 同时返回 song / singer / album / cover，正好够试听弹窗用
- 免费无 key；缺点是音质是低码率试听流（25kbps，整首，约 0.9MB）
- 只支持 QQ 音乐（netease 只给元数据没有 url，kugou 路径 404）

### 内置成兜底

- app/common.php 新增 music_api_mode() / music_vkeys_resolve()
- 接口格式三选一（更多设置 →「音乐授权」里的下拉框）：
  - auto（默认）：先用你填的接口，取不到就用内置的 api.vkeys.cn
  - default：只用你填的接口（原来的梨花带雨格式）
  - vkeys：只用内置免费接口
- 试听（Song::findMusicInfo）和取歌（Api::musicUrl）都走这条链
- 想换成别的 vkeys 镜像：配置 music_vkeys_api 即可（数据库 gui_configs 里加一行）

### 验证

- 试听 QQ 歌 → code 0，返回 发如雪 / 周杰伦 / 封面 / 可播放地址
- 播放接口 /api/musicUrl?...&songId=0027oMO61wWi55&type=qq → 302 跳到 QQ 流地址，跟随跳转实测 206 audio/mpeg
- 试听网易歌 → code -2 + 说明（内置接口只支持 QQ 音乐）
- 接口格式切到 default → 兜底关闭，回到原行为；测试配置项已删除
- 63 个 PHP 文件语法通过；/ 、/console、/admin/moreset.html 均 200


## 上游文档里挖到的更好端点（doc.vkeys.cn = 落月API 官方文档）

- doc.vkeys.cn 就是 api.vkeys.cn 的官方文档站；v2/v3 两版接口都能查到清单。
- QQ 音乐「获取播放链接」专用接口：/v2/music/tencent/geturl?mid=<mid>（支持 quality 参数，
  返回 url / quality / ekey）。付费歌免费额度只给 25kbps「音乐试听」流（实测 206 audio/mpeg），
  免费歌音质更好，会员/无损需要 QQ 音乐 cookie（v2 有扫码取 cookie、cookie 刷新接口）。
- 网易云「点歌（搜索+播放链接整合）」：/v2/music/netease?word=<歌名>&choose=2，
  实测能返回可播放地址；但按 id 查会返回「未找到当前歌曲信息」，只能按歌名搜，
  且可能匹配到翻唱，所以要用它得把歌名+歌手传过去。
- 109a.cn（轩心云API）不适合：音乐类只有酷我/抖音/快手/酷狗铃声，没有 QQ音乐/网易云，
  且大多要密钥计费，接口格式也不是梨花带雨那种 input&filter=id。
