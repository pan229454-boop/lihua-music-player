**修复前最危险的 5 个问题（均已在上面修复）：**

1. **付款成功永不发货**（异步通知里调用了 `checkLogin()`，网关没有 Cookie，直接 exit）

## 八、补充修复：后台「主题」图标与「三个点」图标弹出的是同一个页面

- 现象：后台顶栏「便签」右边的「主题」图标，和右上角的「三个点」图标，点出来都是同一张「版本信息 + 联系客服」页。
- 原因：两个图标分别请求 /admin/system/theme.html 与 /admin/system/about.html，
  但 app/controller/Admin.php 里的 system() 不看子路径，永远 return View::fetch('theme')，
  于是两条请求都渲染 view/admin/theme.html（版本信息页），看起来就是同一个按钮。
- 修复：Admin::system() 按 pathinfo 的末段子路径分发
    theme  -> view/system/theme.html  （layuiAdmin 配色方案 / 自定义配色面板，本来就是给这个图标用的）
    about  -> view/system/about.html  （当前版本 + 关于）
    more   -> view/system/more.html   （手机端「更多」面板：获得产品 / 设置主题 / 本地便签）
    其它   -> 仍返回原来的「版本信息 + 联系客服」页（原有行为不变）
  实现：白名单 theme/about/more + 该视图文件确实存在才渲染，视图都在 view/system/ 下，以后加面板不用改代码。
  坑：pathinfo 是带 .html 后缀的（admin/system/theme.html），要先切掉后缀再比较，否则永远走回退分支。
- 附带：配色面板标题栏加了一个「首页主题设置」按钮（lay-href=/themeset），可直接跳到新的首页主题选择页。

## 九、补充修复：控制面板「实时监控」不动（CPU / 内存 / 负载）

- 现象：控制面板（后台首页）「实时监控」的三条进度条 —— CPU使用率、内存占用率、CPU负载 —— 永远 0%，等多久都不动。
- 原因：两处叠加
  1) app/controller/AdminAjax.php 的 load() 里，Linux 分支的实时监控字段被整段注释掉了
     （连 $count = $this->getLinuxCount(); 一起），接口只返回播放统计；
     前端 updateData() 拿到 undefined，进度条自然不动。
  2) getLinuxCount() 原本靠解析 top -b -n 1 的输出取值，而本机（PRoot 容器）里
     /proc/stat、/proc/loadavg、/proc/uptime 都是 Permission denied，top 既没有 %Cpu(s)
     行也没有 MiB Mem 行，即使放开注释也只会得到 N/A。
- 修复：
  * 内存：直接读 /proc/meminfo 的 MemTotal / MemAvailable，算占用率 + 已用/总量；
  * CPU：先按标准做法读 /proc/stat 两次采样；读不到就降级为统计 /proc/<pid>/stat 里
         所有进程 utime + stime 的增量（容器里也能量到真实变化）；
  * 负载：用 sys_getloadavg()（不依赖 /proc/loadavg），并把原始 1 分钟负载和核数显示在
         标题上，例如「CPU负载(6.55 / 8 核)」；
  * 两种采样合并成一次 200ms 等待，接口耗时从 0.6s 降到 0.33s；
  * 前端 updateData() 增加兜底：遇到 N/A 不再硬塞百分比，而是显示「当前环境不可用」，
    避免以后换环境又变成「进度条不动」。
- 验证：连续请求 /AdminAjax/load 全部 200，CPU 1.25%~5%、内存 61.3%（9.18 GiB / 14.98 GiB）、
        负载原始值 6.55 / 8 核，每次数值都在变；后台各页面与首页回归全部 200。
- 注意：容器里的 /proc/meminfo 与 sys_getloadavg 反映的是宿主机（这台手机）的数据，
        所以负载显示 80% 左右属正常，这台机器本身负载就高。

## 十、补回「服务器状态」菜单与配套接口

- 现象：后台左侧菜单里没有「服务器状态 / 服务器管理」。其实代码大半是有的：
  Admin::serverstate() 和 view/admin/serverstate.html 都在，问题出在两处 ——
  1) AdminAjax::menu() 里那一项被注释掉了（'/serverstate' / '服务器管理'）；
  2) 页面请求的接口 /serverStatus/getStatus 与 /serverStatus/stopProcess 在这个版本里缺失，
     控制器根本没写，所以就算点进去也只会提示「获取服务器状态失败」。
- 修复：
  * 新增 app/controller/ServerStatus.php：getStatus 遍历 /proc 输出进程列表
    （PID / 用户 / CPU% 与累计 CPU 时间 / 内存% 与占用大小 / 命令），
    stopProcess 向指定 PID 发 SIGTERM 停止信号；
  * 权限：未登录按系统规则跳登录页；非管理员（power != 0）返回「你没有权限使用该功能」；
  * 安全：PID 必须是正整数且进程存在；pid <= 1、当前 Web 进程及其父进程，
    以及命令行含 php / mariadb / mysqld / nginx / sshd / systemd / proot / bash / sh / su /
    adb / node / dsh / containerd / cron 等关键字的进程一律拒绝停止；
    界面上这些进程显示「受保护」文字，不会出现「停止」按钮；
  * 菜单：把被注释的菜单项放出来，标题改为「服务器状态」，位置在「订单列表」之后；
  * 视图：顶部加一行概况（进程数 / 受保护数 / 内存总量 / PHP 版本 / 系统），
    CPU、内存两列改为「百分比 + 累计时间 / 占用大小」。
- 验证：菜单第 9 项「服务器状态」→ /serverstate；页面 200；
  接口返回 16 个进程、其中 14 个受保护；stopProcess 实测：
  未登录 → 请登录，pid=0/1 → PID 不合法，pid=999999 → 进程不存在，
  数据库进程 → 「关键进程（含 mariadb）不允许在这里停止」。
  全站页面回归正常，61 个 PHP 文件语法全部通过。
- 注意：容器里 /proc/stat 不可读，CPU% 用两次采样（0.3 秒窗口）的 utime + stime 增量估算，
  所以空闲进程显示 0% 属正常现象；旁边的累计 CPU 时间能看出谁真正吃过 CPU。

## 十一、登录状态保持（不再每次打开都要重新登录）

### 现象
关掉浏览器（或者隔一段时间）再打开站点，就得重新登录一次，很烦。

### 原因
登录成功后程序往浏览器写了三个 Cookie：pskey、skey、sid，但都没有写过期时间，
于是走了 config/cookie.php 里的 expire = 0 —— 这是「浏览器会话 Cookie」，
浏览器一关就全丢了，登录状态自然也没了。
（config/session.php 里的 144000 秒是 PHPSESSID 的，登录状态并不靠它。）

### 修法
1. app/model/Users.php 新增 loginKeepSeconds()：登录和 QQ 登录写 Cookie 时带上有效期
   （原来是 Cookie::set('skey', md5(...))，现在补上第三个参数）。
2. 有效期来自新配置 login_keep_days（单位：天，默认 30 天，最大 3650 天；
   填 0 就恢复成「关掉浏览器就退出」）。
3. 后台「更多设置 → 登录保持」里可以选：关闭浏览器就退出 / 1 天 / 7 天 /
   30 天（默认）/ 180 天 / 一直保持（10 年）。
4. install.sql 里补上 login_keep_days=30 与 chat_enable=1 两条默认配置，新装即生效。

### 验证
- login_keep_days=30 时登录：pskey / skey / sid 都带 expires，Max-Age=2592000（30 天）
- 改成 7 天：Max-Age=604800；改成 0：三个 Cookie 都没有 expires，回到会话 Cookie
- 故意删掉配置行，仍按默认 30 天走（代码里做了兜底）
- 更多设置页面提交到 /AdminAjax/config，字段名 login_keep_days，保存后读回正确
- 登录、退出、首页与后台各页面回归正常

### 注意
- 同一个账号在别的地方登录，先前那台会被顶下线，这是作者原来的单点登录设计，这次没有改。
- 改完设置要重新登录一次才生效，因为已经发出去的 Cookie 还是按旧的时间走。
